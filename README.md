# 눈으로 하는 디버깅 — 부스 진행 화면

**배포 주소: https://twkim02.github.io/aloha-skku-hyu-cse-2026/**

행사장에서는 인터넷 없이 로컬에서 `index.html` 을 여는 쪽을 권합니다.
외부 요청이 하나도 없어 오프라인으로 완전히 동작하고, 행사장 와이파이에
영향을 받지 않습니다. 배포본은 다른 부원과 공유하거나 예비용으로 쓰시면 됩니다.

## 실행

`index.html` 을 브라우저에서 열면 됩니다. 설치도, 서버도, 인터넷도 필요 없습니다.

부스에서는 크롬으로 열고 **F11**(맥은 `⌃⌘F`)로 전체화면을 켜 두시면 됩니다.
첫 화면의 `시작하기` 를 누를 때도 전체화면을 자동으로 시도합니다.

## 진행 방법

1. **시작하기** 를 누릅니다
2. 참가자가 **초급 / 중급 / 고급** 중 하나를 고릅니다
3. 참가자가 준비되면 **시작하기** — 이 순간 문제와 타이머가 같이 시작됩니다
4. 제한시간(초급·중급 30초 / 고급 60초)이 끝나면 화면에 `시간 종료` 가 뜹니다.
   정답은 저절로 나오지 않습니다
5. **정답 보기** 를 누르면 틀린 줄이 강조되고 설명이 나옵니다.
   참가자가 일찍 맞히거나 포기했으면 시간이 남아도 누르셔도 됩니다
6. **처음으로** 를 눌러 다음 참가자를 받습니다

문제는 난이도별로 무작위로 나오되, 한 바퀴를 다 돌기 전에는 같은 문제가 다시
나오지 않습니다. **페이지를 새로고침하면 이 기록이 초기화되므로**, 부스 운영
중에는 새로고침하지 말아 주세요.

## 문제 추가·수정

문제는 난이도별 폴더에 JSON 파일 하나씩으로 들어 있습니다.

```
questions/
  easy/    01-array-index.json  02-assign-vs-equal.json  ...
  medium/  01-star-pattern.json  ...
  hard/    01-hanoi-base-case.json  ...
```

**난이도는 폴더가 정합니다.** 문제를 초급에서 중급으로 옮기고 싶으면
파일을 `medium/` 으로 옮기기만 하면 됩니다.

### 순서

1. `questions/<난이도>/` 안에 JSON 파일을 새로 만들거나 고칩니다
   (기존 파일을 복사해서 내용만 바꾸는 게 가장 빠릅니다)
2. **`build.command` 를 더블클릭합니다**
3. 브라우저에서 `index.html` 을 새로고침합니다

2번을 빼먹으면 화면에 반영되지 않습니다.
(`index.html` 은 `questions.js` 를 읽는데, 이건 `build.command` 가 JSON 들을
합쳐서 만드는 파일입니다. 브라우저가 `file://` 에서 JSON 을 직접 읽지 못해서
이렇게 되어 있습니다.)

### JSON 형식

```json
{
  "prompt": "틀린 곳을 찾으세요",
  "lang": "Python",
  "input":  ["5"],
  "output": ["15"],
  "code": [
    "n = int(input())",
    "ans = 0",
    "for i in range(1, n+1):",
    "    ans = ans + n",
    "print(ans)"
  ],
  "bad": [4],
  "answer": "ans = ans + n   →   ans = ans + i",
  "note": "현재 코드는 n을 n번 더해서 n × n 이 나오는 코드입니다."
}
```

| 항목 | 필수 | 설명 |
|---|---|---|
| `prompt` | ○ | 문제 한 줄입니다. `"틀린 곳을 찾으세요"` / `"출력 결과를 예측하세요"` |
| `lang` | | 코드블록 오른쪽 위에 뜨는 언어 이름입니다. `"C"` `"C++"` `"Python"` |
| `input` | | 화면 **왼쪽 위**에 뜨는 입력입니다. 한 줄이 배열 항목 하나입니다 |
| `output` | | 화면 **왼쪽 아래**에 뜨는 원하는 출력입니다. 한 줄이 배열 항목 하나입니다 |
| `code` | ○ | 화면 **오른쪽**에 뜨는 코드입니다. 한 줄이 배열 항목 하나이고, 빈 줄은 `""` 로 적습니다 |
| `bad` | | 정답을 공개할 때 강조할 줄 번호입니다. **화면에 보이는 줄 번호를 그대로 적으시면 됩니다** |
| `answer` | ○ | 정답 한 줄입니다 |
| `note` | | 한 줄 설명입니다 |

**화면 배치는 `input` / `output` 이 있느냐로 정해집니다.**

- 둘 중 하나라도 있으면 → 왼쪽에 입출력, 오른쪽에 코드 (틀린 곳 찾기 문제)
- 둘 다 없으면 → 코드만 화면 전체 폭으로 크게 (출력 예측 문제.
  출력을 보여주면 답이 새어나가므로 넣지 않습니다)

`input` 은 stdin 만을 뜻하지 않습니다. **이 코드에 주어진 값**을 적으시면 됩니다.
함수 문제라면 `["n = 12", "i = 2"]` 처럼 인자를 적으면 되고, 별 찍기처럼 주어진 값이
정말 없는 문제는 `input` 을 빼면 출력 칸이 위로 올라옵니다.

- 코드 안의 큰따옴표는 `\"`, 역슬래시는 `\\` 로 적습니다.
  `printf("\n");` 은 `"printf(\"\\n\");"` 가 됩니다 — JSON 규칙 그대로입니다
- 한글이 섞인 값은 본문 폰트로, 프로그램 값은 등폭 폰트로 알아서 나옵니다
- 코드 글자 크기는 길이에 맞춰 자동으로 줄어드니 신경 쓰지 않으셔도 됩니다
- 코드 왼쪽에는 줄 번호가 자동으로 붙습니다. `code` 배열의 순서와 화면의 줄 번호가
  같으므로, `bad` 는 화면에서 본 번호를 그대로 적으시면 됩니다

`build.command` 는 형식이 틀리면 어디가 왜 잘못됐는지 알려 주고, **그럴 때는
`questions.js` 를 건드리지 않습니다.** 고치고 다시 돌리시면 됩니다.

## 배포본 갱신

문제를 고친 뒤 배포 주소에도 반영하려면 이렇게 하시면 됩니다.

```bash
./build.command          # 또는 더블클릭
git add -A
git commit -m "문제 추가"
git push
```

푸시하고 1~2분 뒤에 반영됩니다. **`build.command` 를 먼저 돌려야 합니다** —
배포된 페이지는 `questions.js` 를 읽는데 GitHub 쪽에는 빌드 단계가 없습니다.

## 파일

| 파일 | 내용 |
|---|---|
| `questions/` | **문제 원본입니다. 보통 여기만 고치시면 됩니다** |
| `build.command` | 더블클릭하면 `questions/` 의 JSON 을 `questions.js` 로 합칩니다 |
| `index.html` | 슬라이드 4개의 뼈대입니다 |
| `app.js` | 슬라이드 전환, 타이머, 문제 뽑기를 담당합니다 |
| `style.css` | 화면 스타일입니다 |
| `assets/logo.png` | 첫 화면 로고입니다 (원본 `로고.png` 을 잘라 줄인 것입니다) |
| `questions.js` | **자동 생성 파일입니다. 직접 고치지 말아 주세요** |
| `build.py` | `build.command` 가 실제로 실행하는 스크립트입니다 |
